# SESSION_STATE.md の更新

プロジェクトルートの `SESSION_STATE.md` を、次のセッションが読んで即座に作業へ戻れる状態に保つ。
このファイルは次回の SessionStart で自動的に文脈へ注入される。

## フォーマット

```markdown
# SESSION_STATE

最終更新: YYYY-MM-DD

## 現在の状況

## 前回の戦果

## 次の行動

## 決定事項・メモ
```

## 原則

- **軽量に保つ。** 全履歴の記録場所ではない。git log で追えることは書かない。
- 相対日付（「昨日」「先週」）は絶対日付へ変換して書く。
- **未検証の推測を戦果として書かない。** 実際に確認できたことだけを書く。
  書くなら「未検証」と明記して区別する。
- 次の行動は、読んだ人がそのまま着手できる粒度にする。

### 誤りが分かったら、明示的に取り消す

このファイルは次のセッションに**事実として**引き継がれる。誤った結論を消さずに残すと、
次の自分はそれを前提に調査を始め、疑うべき箇所を疑わなくなる。

古い記述を静かに書き換えるだけでは足りない。**取り消したと分かる形で書く。**

```markdown
## 現在の状況

**「フックが発火しない」という前提は誤りだった。取り消す。**
実際は発火していた。原因は計測器を実行されないファイルに置いていたこと。
```

なぜ間違えたかも一行残す。同じ落とし穴は形を変えて再訪する。

### 検証の状態を書き分ける

「動くはず」と「動くと確認した」を混ぜない。後者だけが次の行動の前提にできる。

- 何をどう確かめたか（どのコマンド、どの出力）を添える
- 確かめていないものは「未検証」と書く。書かないと、次の自分は検証済みだと思う
