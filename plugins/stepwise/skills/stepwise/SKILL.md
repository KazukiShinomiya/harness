# 1 件ずつ承認しながら進める

手順をまとめて流さない。1 件見せて、承認をもらい、実行し、結果を見せてから次へ進む。

## 始めに

1. 全体の手順を番号付きで短く示す（1 行 1 手順）。各手順は、それだけで実行と確認ができる大きさにする。
2. この一覧そのものにも同意をもらう。手順の追加・削除・入れ替えを言われたら直してから始める。

## 各手順の回し方

1. **何をするか**を一言で書く（目的、変わるもの）。
2. **実行する中身をそのまま見せる。** コマンド、または差分。要約で済ませない。
3. **承認を待つ。** AskUserQuestion で「実行する / 変更する / 飛ばす / 止める」を選んでもらう。
   - 返事の無いまま次へ進まない。過去の承認を別の手順へ流用しない。
   - 「任せる」と言われても、それはその手順だけの承認として扱う。
4. 承認された中身**だけ**を実行する。見せたものと違うコマンドを走らせない。直す必要が出たら、直したものをもう一度見せる。
5. **実際の結果を報告する。** 終了コードと出力の要点。「できたはず」と書かない。
   - 出力が空・想定外・失敗なら、そこで止まる。原因を調べて報告し、どうするかを聞く。
6. 次の手順へ。残りの手順を一覧で示す。

## ユーザー自身が実行する手順

`~/.claude` の設定、認証、課金が絡むものなど、ユーザーが自分で実行すると決めているものは、
コマンドを見せて**実行してもらい、貼ってもらった結果を確かめてから**次へ進む。
可能なら、先に複製や一時ディレクトリで同じ操作を試し、差分を見せておく。

## してはいけないこと

- 複数の手順を 1 回の承認でまとめて実行する
- 承認を待たずに「ついでに」別の変更を足す
- 失敗した手順を黙って飛ばす、または別の方法で勝手にやり直す
